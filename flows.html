THE REAL SHAPE OF THE QUESTION

"Show me everything that's going to fire" is actually four different questions, and they need four different pictures. The field mostly ships all four; the mistake would be building one screen that half-answers each.

View 1 · a tableWhat automations exist, and are they on?The registry. Would have caught the 28 Litsea bug: reminders live for MD, silently dead for 28 Litsea.
View 2 · a queueWhat fires next, concretely?Time-ordered upcoming sends with hold and cancel. Would have caught the invite text firing instantly instead of after 2h.
View 3 · a mapHow do messages chain?The flow canvas: trigger, wait, condition, message. The "low-code look", generated from the real rules.
View 4 · a timelineWhat is coming for THIS creator?The per-person path: what she got, where she is, what is queued for her and under which condition.

1The canvas: the low-code look, and what belongs on a node

Klaviyo · Attentive · Twilio Studio · ActiveCampaign · n8n · Intercom Series

Every serious messaging system converged on the same drawing: trigger on top, messages as cards, waits and splits between them. What separates the good ones is how much truth the node face carries: the actual first line of copy, the channel, the live status, and the outcome branches.

In the command center: our flows are stage-driven, not drip sequences, so the honest canvas is the campaign stage ladder as a spine, message nodes hanging off each transition and timer, one swimlane per fork (product, local, brand-reviews-content). Node face shows: intent name, the base copy's first line, channel, Live/Draft/Held, and Twilio-Studio-style outcome chips. Agent-edited nodes get the Intercom purple tint.

2Criteria, waits, and the rules that cancel a send

Postscript · Klaviyo · Customer.io · Attentive · OneSignal

"The agents will fire if the creators fill different criteria" is exactly what these panels draw. The best pattern makes eligibility one readable sentence stack, waits into visible nodes with escape hatches, and, most important for trust, puts everything that cancels a pending message in one place.

In the command center: every automation's page opens with its Postscript-style sentence stack: fires when, but only if, held while, canceled by. The "canceled by" list is where the intelligence layer becomes visible: away-until-Wednesday, already replied, consent missing, thread owned by Katie. That list is precisely what was missing when the vacationing creator still got her 3-day reminder.

4What fires next: the queue, the calendar, the countdown

Klaviyo · Customer.io · Buffer · Postscript · OneSignal

The flow map answers "how does it work"; this view answers "what exactly goes out, to whom, at what time". Katie paused the invite text precisely because she could not see its fire times. The field has three shapes for it: the per-recipient table, the per-person countdown roster, and the calendar.

In the command center: a "Next 24 hours" tab: Klaviyo's table (creator, intent, campaign, fire time, hold and cancel per row) grouped by hour, with Buffer's week calendar as the zoomed-out view for wave planning (re-invite blasts, launch days). Every row links to the ghost bubble in that creator's thread. Quiet hours render as shaded bands on the calendar so held night sends are visibly parked, not missing.

5Counts on the map: the canvas as the monitor

Klaviyo · Intercom Series · Attentive · Braze · n8n

Once numbers live on the nodes, the same drawing that defines the flow becomes the dashboard that watches it. This is Brian's "surfacing abnormalities" rendered spatially: creators piling up at a wait step, or a branch quietly sending zero.

In the command center: the flow map gets a stats overlay toggle: creators currently waiting at each node, sends per node this week, held count per node (the agent's suppressions made visible), and a red ring on any node whose 7-day sends dropped to zero while its brand stayed active. The n8n-style ranked health table is the home-page abnormality strip's drill-down.

7Rehearsal: prove it before it's armed

Klaviyo · HubSpot · Twilio Studio · Intercom · n8n

The counterpart of shadow mode, for flows: pick a person, run them through, watch the route light up. Every serious system ships a version of this, and it is what turns "I think this automation is right" into "I watched it be right".

In the command center: the playbook test box from Part 1, extended to flows: pick a real creator, watch her route light up on the map with the matched conditions proven, and a standing test-numbers allowlist (Katie's and Julia's phones) that any draft flow can fire at. Editing a criteria row instantly shows "would match 41 creators across 3 brands".
HOW TO VISUALIZE IT

The answer to "how do we best visualize the pre-scheduled?"

  1. Build four linked views, not one screen. Registry matrix (what exists, per brand), the next-24h queue plus calendar (what fires), the flow map (how it chains), and ghost bubbles (what is coming for this creator). Every view links into the others: matrix cell to map node to queue rows to thread bubbles.
  2. The canvas is generated, never hand-drawn. This is the reconciliation with the Aug 18 no-DSL decision: Brian's dependency graph and the Rails triggers are the source of truth, and the map is rendered from them, like ActiveCampaign's auto-generated Automations Map or n8n's execution view. If the map can drift from reality, it will, and Katie will stop trusting it.
  3. Low-code look, read-heavy, control-light. Katie's edit surface on the map is parameters: pause and resume per automation per brand, timing changes, holds, audiences. Structure changes come from agents and Brian. That is the exact split from the call: she gets "stop this onboarding text for this population" without waiting on anyone, and nobody hand-wires spaghetti.
  4. Nodes are intents, not copy. The agent personalizes wording per thread, so the map shows "3-day reminder" with the base copy's first line, and the per-creator adaptation lives in the ghost bubble. Held counts on nodes make the intelligence layer's suppressions visible instead of spooky.
  5. Waits, exits and quiet hours are drawn, not implied. Wait-until nodes with escape lanes (Customer.io), exit rules in one panel (Attentive), time windows as nodes (OneSignal). Everything that delays or cancels a message is on the picture.
  6. Numbers live on the drawing. Waiting, sent and held per node; counts on branch edges; a red ring for "live but silent 7 days". The map doubles as the abnormality monitor Nisarg called the most important part.
  7. Diffs are first-class. Intercom's purple tint on changed blocks becomes essential once agents edit flows: Katie opens the map and sees what the machine changed since she last looked, with a changelog per automation.
  8. Rehearsal beats review. Preview-as-creator with the route lit up, live audience counts on every criteria edit, and a test-numbers allowlist. No flow arms without having been walked.
Where I would start. Build in the order the views pay off: the registry matrix and the next-24h queue first. Both are renderings of data Rails already has, both would have caught real bugs from the last two weeks (28 Litsea's dead reminders, the instant invite text), and neither depends on Brian's system existing yet. Then ghost bubbles, which ride on Nisarg's new admin creator tab and make the whole system feel trustworthy per creator. The generated flow map comes last, once Brian's dependency graph exists to generate it from, and arrives with counts-on-nodes and the purple diff tint on day one. Worth bringing to the Brian kickoff as the visualization roadmap, alongside Part 1 for the conversation side.
