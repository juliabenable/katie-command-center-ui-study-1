THE FRAMING THAT SHRINKS THE BUILD

Requirements 1, 2 and 3 (all texts · agent texts per person · when the agent needs Katie) are one data source rendered three ways: the message log Rails already has, plus the flag object Brian's engine must produce anyway to hold a weird send. Requirement 4 (the trees) is the only different thing, and it ships as a static page, not a canvas. The decision rule for every cut below: MVP contains only what the shadow and draft-approval phases physically need to operate. Anything whose value depends on 5x volume waits until the volume exists.

Sizing: one new table (flags), one new field (message author), three endpoints, two list views, one thread panel, one generated static page, one Slack webhook. Julia's biweekly auditing (level 3) costs zero UI: Workbench access, as agreed with Brian.

5The flag contract: the interface between Brian's engine and this UI

Agree this shape Thursday and both sides can build without waiting on each other
flag { id, creator_id, campaign_id reason: "product_problem" // from the escalation topic list reason_text: "creator mentions a product problem" held_message: { intent: "MSG-06", body: "..." } // what was queued, now held draft: { body: "..." } // what the agent proposes instead context_note: "3-day reminder was due today; holding until resolved" created_at, expires_at // stale flags re-verify on approve resolution: approved | edited | dismissed // any action clears the flag resolved_by, resolved_at } message.author = katie | automation | agent | creator // the one new field on messages

Two rules ride the contract: a flag auto-clears on any action (approve, edit, dismiss, or Katie replying in the thread herself), and an approved draft is re-verified against fresh state at send time, the MDSolarSciences stale-context lesson. Compliance gating (consent, STOP, quiet hours) stays in Rails middleware and is not this UI's job.

The one-sentence answer to the overbuild fear. Ship the ledger and the queue, not the command center: one page whose two tabs and thread panel are three renderings of data the system produces anyway, plus a static ladder page generated from a document you are already writing. If Katie lives in it, V1 earns its keep with real usage data; if she does not, we learned it for the price of a week, not a quarter.
